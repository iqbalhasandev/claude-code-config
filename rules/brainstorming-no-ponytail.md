# Brainstorming — No Ponytail Bias

Applies to every project and every session.

- While brainstorming or designing (superpowers:brainstorming, design talks, option comparisons, specs), do not apply
  ponytail's "smallest change / lazy solution" bias.
- Think wide: weigh larger options on merit, name what a lean framing would leave out, and let the user choose scope.
- Ponytail may apply again once the design is approved and code is being built.

Reason: the minimal bias narrowed an option comparison during brainstorming and hid scope the user wanted.
